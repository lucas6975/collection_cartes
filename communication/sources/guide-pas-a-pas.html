AGitHub : le dossier du projet

GitHub garde tout le code de l’appli et l’historique de chaque modification.

  1. Va sur github.com › Sign up : e-mail, mot de passe, nom d’utilisateur (il apparaîtra dans l’adresse du site, ex. lucas6975).
  2. Une fois connecté : bouton + en haut à droite › New repository.
  3. Repository name : le nom du projet, sans espace ni accent (ex. collection_cartes). Il sera aussi dans l’adresse du site.
  4. Choisis Public (GitHub Pages est gratuit pour un dépôt public) et coche Add a README file.
  5. Create repository. Ton dépôt existe : github.com/ton-pseudo/nom-du-projet.

💡 Un dépôt public veut dire que tout le monde peut lire le code. C’est sans danger tant qu’aucun secret n’y est écrit (mot de passe, code admin, clé privée).

BClaude Code : l’assistant qui code

C’est lui qui écrit tout le code, le teste et l’envoie sur GitHub. Toi, tu décris et tu valides.

  1. Va sur claude.ai/code et connecte-toi avec ton compte Claude (abonnement nécessaire).
  2. Relie GitHub : Connect GitHub › autorise l’appli Claude sur GitHub › choisis ton dépôt (ou « All repositories »).
  3. Choisis le dépôt dans la liste, puis écris ta demande dans la zone de texte et envoie.
  4. Claude travaille dans une copie du projet dans le cloud, montre ce qu’il fait, puis envoie le code sur GitHub (un « commit » sur une « branche »).
  5. Tu peux suivre et répondre depuis l’ordinateur ou l’appli Claude sur ton téléphone.

Exemple de première demande

« Crée une appli web pour téléphone (installable sur l’écran d’accueil) pour sensibiliser mes collègues à [ton sujet]. Chaque jour, les gens [ce qu’ils font]. Style : couleurs [tes couleurs], mascotte [ton personnage].
Fais-moi d’abord une maquette avant de programmer. Publie le site sur GitHub Pages. »

Mes règles qui marchent

🖼️ Toujours une maquette d’abord, puis « vas-y, programme ».
🎯 Une demande à la fois, précise : « mets le bouton en bas », « couleur jaune ».
📸 Envoie des captures d’écran quand quelque chose ne va pas.
🔒 Ne colle jamais un secret dans la conversation (code admin, mot de passe).

CGitHub Pages : le site en ligne

GitHub publie le site gratuitement, à chaque modification, à une adresse qui ne change jamais (celle du QR code).

  1. Demande à Claude : « Ajoute la publication automatique sur GitHub Pages avec GitHub Actions ». Il crée un fichier .github/workflows/deploy.yml.
  2. Sur GitHub, dans ton dépôt : onglet Settings › menu de gauche Pages.
  3. Rubrique Build and deployment › Source : choisis GitHub Actions.
  4. Onglet Actions du dépôt : chaque publication apparaît. Rond vert ✅ = en ligne (environ 2 minutes). Croix rouge ❌ = envoie la capture à Claude.
  5. Ton site : https://ton-pseudo.github.io/nom-du-projet/. C’est ce lien qu’on met dans le QR code.

⚠️ Si la publication refuse la branche de Claude (« not allowed to deploy ») : Settings › Environments › github-pages › Deployment branches : ajoute la branche indiquée, ou demande à Claude de fusionner dans main.

DSupabase : la base de données

Seulement si l’appli doit partager des données entre téléphones (inscriptions, tirages, résultats…).

  1. supabase.com › Start your project › Continue with GitHub (le plus simple).
  2. New project : Name (ex. team-ulysse), Database Password (note-le et garde-le pour toi), Region : Europe (Paris) › Create new project. Attendre 1 à 2 minutes.
  3. Demande à Claude les fichiers SQL pour ton appli : il les crée dans le dossier supabase/ du dépôt.
  4. Pour chaque fichier, dans l’ordre : menu de gauche SQL Editor › New query (onglet vide) › colle tout le fichier › Run. Message attendu : « Success. No rows returned ».
  5. Récupère les deux infos de connexion : roue dentée Project Settings › API Keys / Data API : Project URL et la clé publishable (ou « anon public »). Donne-les à Claude : il les met dans le code.
  6. Pour voir les données : Table Editor › clique sur une table.

✅ Publiques, sans danger : la Project URL et la clé publishable / anon (elles sont dans le site).

🔒 À garder secret : le Database Password, la clé secret / service_role, ton code admin.

⏸️ Offre gratuite : le projet se met en pause après 7 jours sans activité (e-mail d’avertissement). Rien n’est perdu : ouvrir le projet › Restore project.

ELes notifications (optionnel)

Pour envoyer un rappel chaque matin sur les téléphones. Demande à Claude : « Ajoute des rappels par notification, et explique-moi la mise en place dans Supabase ».

  1. Les clés VAPID (une paire de clés pour signer les notifications) : Claude peut les générer. La publique va dans le site ; la privée reste secrète.
  2. Supabase › Edge Functions › Deploy a new function › Via Editor. Nom : celui donné par Claude (chez moi envoyer-rappels).
  3. Remplace tout le code par le fichier « tout-en-un » préparé par Claude › Deploy function.
  4. Dans les réglages de la fonction : désactive « Verify JWT » / « Enforce JWT verification » › enregistrer.
  5. Edge Functions › Secrets › ajoute chaque secret (nom + valeur), ex. VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY.
  6. Lance le fichier SQL des rappels (SQL Editor › New query › Run) : il crée la tâche programmée (pg_cron) qui appelle la fonction chaque matin.
  7. Sur le téléphone : ouvre l’appli depuis son icône (obligatoire sur iPhone) › active les rappels › fais envoyer une notif de test.
