Comment j’ai créé
Team Ulysse

Une appli sécurité dans la poche des salariés, sans serveur à gérer et à 0 € d’hébergement : un assistant IA pour écrire le code, GitHub pour le publier, Supabase pour la base de données.

1Le schéma d’ensemble

🤖Claude CodeAssistant IA : j’explique l’idée, il écrit le code et me montre des maquettes
➜
🗂️GitHubGarde tout le code et l’historique des modifications
➜
🚀GitHub PagesPublie le site tout seul en ~2 min à chaque modification
➜
📱Téléphones« Ajouter à l’écran d’accueil » : le site devient une appli
🗄️
SupabaseBase de données (PostgreSQL) : inscrits, tirages, résultats, échanges… On la remplit en copiant-collant des fichiers SQL.
🔔
NotificationsUne « Edge Function » Supabase envoie les rappels chaque matin (tâche programmée pg_cron + Web Push).

2Les étapes, dans l’ordre

① L’idée et les maquettesJe décris ce que je veux (cartes, packs, calendrier de l’Avent…). L’IA propose une maquette ; je valide ou je corrige avant qu’elle code.
② Le codeSite en React + TypeScript (outil Vite, style Tailwind). La collection de cartes est enregistrée sur le téléphone : pas de compte, pas de mot de passe.
③ La publicationLe code est envoyé sur GitHub. Une « GitHub Action » vérifie (tests) puis publie sur GitHub Pages : le lien du QR code ne change jamais.
④ La base SupabaseCréer un projet gratuit sur supabase.com, copier son URL et sa clé publique « anon » dans src/config.ts, puis lancer les fichiers SQL (à droite ↓).
⑤ Les notificationsCréer des clés VAPID, les mettre dans les Secrets de Supabase, coller la fonction envoyer-rappels (fichier tout-en-un.ts) puis « Deploy ».
⑥ Le lancementQR code, affiches, vidéo, publication Viva Engage… et l’espace admin pour suivre les inscriptions et les packs en direct.

3Les fichiers SQL à copier-coller

  1. setup.sql — inscrits, tirages, code admin (à changer avant Run !)
  2. maj-weekends.sql — pas de tirage le week-end
  3. maj-corrections.sql — corrections des cases du calendrier
  4. maj-coalition-et-rappels.sql — volontaires + rappels du matin
  5. maj-echanges.sql — échange de cartes par QR code
  6. maj-gagnant-et-resultats.sql — notif du gagnant + résultats
  7. maj-lancement.sql — onglet Lancement de l’admin
  8. maj-visites.sql — « Du lien à l’inscription »
  9. maj-packs.sql — qui a ouvert son pack du jour
  10. maj-notif-inscrits.sql — alerte « Nouvel inscrit »

Dans Supabase : SQL Editor › New query › coller tout le fichier › Run. Un fichier à la fois, dans l’ordre. Ils sont tous dans le dossier supabase/ du projet GitHub.

4À quoi ressemble le SQL

-- Une table fermée : le site ne peut pas la lire
create table public.participants (
  id uuid primary key default gen_random_uuid(),
  prenom text not null,
  nom text not null,
  inscrit_le timestamptz default now()
);
alter table public.participants
  enable row level security;

-- Le site passe seulement par des fonctions
create function public.inscrire(
  p_prenom text, p_nom text) ...
grant execute on function
  public.inscrire to anon;
  • Les tables sont fermées ; le site appelle des fonctions précises.
  • Le code admin est stocké chiffré dans la base.

🔒 Ne jamais partager : le code admin, la clé VAPID privée, la clé « service_role » de Supabase.
